# 可选R2直传：50MiB分片，6个并发

管理员上传页新增“服务器中转”和“R2直传（保存原图）”，默认中转。
直传限管理员关联的标准R2 S3策略，小文件也能直传。游客和其他存储仍走原流程。
服务器中转保持50MiB、3并发；R2直传为50MiB、6并发。

## 首次使用

1. 更新镜像并重新创建原容器，保留现有环境变量、端口、数据卷和数据库。
2. Cloudflare → R2 → 对应桶 → 设置 → CORS策略，添加 [规则文件](r2-direct-cors.json) 中的规则。
   已有其他站点的规则必须保留并合并，不要覆盖删除。AllowedOrigins应是实际上传页面origin，示例为https://dayv.cc；新站dayv.io需改为https://dayv.io，不是下载域名r2.dayv.cc。
3. 管理员组保存质量为100，关闭格式转换、水印和审查。需要这些处理时选择中转，服务器不会允许直传绕过组要求。
4. 刷新上传页，选择R2策略和“R2直传”，重选图片。页面显示“正在校验文件”、“R2直传中”、“确认文件并保存记录”。

浏览器直接PUT到标准R2 S3端点的30分钟签名地址，不能替换为自定义下载域名。
密钥留在服务器；网站CSRF头和会话Cookie不会发给R2。签名过期会刷新一次。
网站可以继续开启小黄云，只有较小的控制请求经过VPS。

## 校验和恢复

- 浏览器分块计算完整文件MD5/SHA1和每片MD5，每次只读取1MiB，避免整图ArrayBuffer。
- 签名绑定Content-MD5，R2校验各片内容。完成前服务器读取真实ListParts，核对序号、数量、大小和ETag/MD5。
- R2合并分片，VPS不暂存、合并或转发完整文件。完成后校验HeadObject总长度和任务标记，并读取首64KiB识别图片类型和尺寸（相机JPEG尺寸尚未出现时，最多读取4MiB文件头），再创建图片记录。
- 完整MD5/SHA1由管理员浏览器计算，服务器没有下载整个对象复算；没有基于客户端哈希复用其他图片的直传捷径。
- 普通图片先读取64KiB；相机JPEG的大型EXIF/ICC/APP段可能把尺寸放在更后面，会追加一次最多4MiB的范围读取，不下载整张原图。不解码像素；超过此上限仍无法识别或真实格式不匹配时，显示明确失败提示并清理临时对象，改用中转。
- 保存原图，不压缩、不加水印、不生成缩略图；大于50MiB且没有缩略图时显示占位预览，点开才下载原图。沿用组命名规则，优先保留原文件名（例如 `IMG_7338.png`）；同一桶/路径已有对象、图片记录或待完成直传任务时，才添加6位随机十六进制编码（例如 `IMG_7338-a7c9e2.png`），短编码冲突则重新生成。已上传图片和续传任务的链接不改名。命名预留使用共享任务目录的文件锁；多个独立实例需要共享该目录。请避免其他工具在直传期间向同一对象路径写入；完成前会再检查是否被外部占用。
- 刷新后重选相同文件、同一策略可续传；实际已接收片从R2获取。网络/408/429/5xx最多重试3次。
- 初始化或完成响应丢失会恢复现有任务/对象；重复提交不会重复创建图片记录。成功结果保存24小时。
- 校验管理员身份、账号状态、组策略、文件上限和用户容量；完成时执行上传频率检查。文件上限512MiB，最多3个未完成大文件任务。预留计入同用户其他直传和中转任务。
- 9.5GB全部归档已集成，默认关闭；Worker、TG服务和启用步骤见 [归档手册](r2-archive-telegram.md)。

## 清理和速度

现有每小时uploads:prune-chunks会终止24小时未更新的R2任务，不删除已写入数据库的对象。
建议给R2桶配置“不完整multipart上传超过1天后终止”的生命周期规则，兜底处理创建远端任务但没收到upload ID的情况；不要设置删除完整图片的规则。
endpoint/bucket更改后，清理不会使用新配置猜测删除旧桶任务，需要旧桶生命周期或原配置处理。

6并发不保证比3并发快，速度仍取决于手机到R2线路。此路径省去了VPS中转和第二次传输。

## 相机 JPG 停留在“确认文件并保存记录”

先查看 `/complete` 的响应和任务 phase。HTTP 200 也可能包含 `status:false`；aborted 表示任务已终止，不代表还在合并。包含大量 EXIF/ICC 的相机 JPEG 可能需要扩展文件头读取，新版支持最多4MiB。前端会显示业务失败原因，并允许重选文件时自动丢弃已终止的续传编号。请更新后强制刷新上传页，再重新选择原文件；不要手工把 aborted 改为 recorded 或跳过文件格式验证。

## 小文件与上传组件

当前R2直传统一走multipart接口。小于等于50MiB的文件只有一片，不会切成六片；六并发是大文件同时在途的最大分片数。小文件仍有创建/确认任务的开销。

旧版把blueimp组件初始化在文件输入框上，选择文件后输入框被替换，完成回调引用旧元素会报 `cannot call methods on fileupload prior to initialization`。新版将组件挂在稳定容器并显式指定fileInput，兼容反复选择、分片完成和失败回调。更新后清除Blade缓存并强制刷新页面。真实blueimp/jsdom测试覆盖该替换行为，不再只依赖模拟回调。
