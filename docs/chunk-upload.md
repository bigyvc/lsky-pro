# 50MB 分片上传（3 个并发）

基于 bigyvc/lsky-pro 提交 aaae7536a65ba78da5487452ee44768453f614d6。
这里的 50MB 按二进制单位解释：每片 50 × 1024 × 1024 字节（50 MiB）。

## 行为

- 所有大小的文件统一使用分片接口；不超过50MiB的文件只有一片，多个文件仍按角色并发设置同时上传。
- 一张大文件最多同时发送3片；同时上传的文件数遵循角色组“并发上传”设置，0 表示不设应用层上限，正整数表示同时处理的文件数。多个文件同时上传时，分片请求数量会叠加。
- 暂存于非公开的 storage/app/upload-chunks，按登录用户或游客会话隔离。
- 网络错误、408、429、5xx最多重试3次；权限、413和校验错误不反复重传。
- 刷新后重新选择相同文件可续传：浏览器保存任务号，使用文件名、大小、修改时间和首尾各1MiB样本的SHA-256识别文件。该样本指纹不是完整文件校验和。
- 浏览器清除网站数据、游客会话丢失、文件内容/修改时间变化、任务24小时未更新时，不能接续旧任务。
- 服务器检查每片长度；重复片比较SHA-256，内容冲突拒绝覆盖；收齐后按序磁盘流式合并，核对总长度。
- 提交结果缓存，网络丢失响应后重试不会重复创建图片记录。外部存储/数据库提交中断、无法确认成功时，不会盲目再提交；先检查“我的图片”，必要时重新建任务。
- 合并后的完整文件重新走原 ImageService：角色限额、用户容量、存储策略权限和图片审查仍然有效。
- 用户容量检查计入同一用户其他待完成分片任务的预留大小。最多3个未完成大文件任务，小文件不占用这3个大文件名额；总任务数最多1000，合计预留最多1.5GiB。
- R2 策略由管理员自动直传；TG 等其他策略仍通过服务器暂存分片并交给原存储流程。9.5GB 自动归档配置见 [归档操作流程](r2-archive-telegram.md)。
- 大于50MiB或预计图像工作内存超过128MiB（像素×16）的文件跳过重编码、水印和缩略图，保留原始图片。启用图片审查时仍会按原配置审查。
- PHP upload_max_filesize保持512M，post_max_size调为544M，给表单开销留空间。不改变现有PHP内存设置。
- 上传统一显示“上传中…百分比”，最终确认期间保持99%，存储完成才显示成功。

## 应用到当前容器

补丁包里的 src/ 是覆盖文件，不是完整应用。先暂停上传，在服务器解压补丁包，进入其目录：

```bash
bash tools/install-chunk-upload.sh lsky-pro
```

脚本会先校验全部待覆盖文件。若当前文件与审核基线/补丁版本均不一致，**停止且不覆盖代码**，避免破坏你自行添加的R2迁移逻辑。需要合并这些自定义差异后才能安装。

校验通过后逐个备份原文件、复制补丁，清理视图与路由缓存，设置post_max_size=544M并平滑重载Apache。脚本打印备份目录。

热补丁不更新当前镜像，也没有经过你真实服务器的部署验证。容器重建/升级前，务必将相同源码改动合并到仓库并构建新镜像；否则可能回到旧代码。没有修改数据库结构，无需执行数据库迁移。

热补丁安装器在宿主机有 /etc/cron.d 且以root执行时写入每小时清理任务，cron服务必须运行。
若系统没有cron，安装启用cron，或手动执行：

```bash
docker exec -u www-data -w /var/www/html lsky-pro php artisan uploads:prune-chunks
```

从更新后的Dockerfile重建镜像时，entrypoint自带每小时清理循环，无需宿主机cron。

## 合并到GitHub仓库

把补丁包中对应的源码、Dockerfile、entrypoint.sh、测试和workflow文件覆盖到仓库同路径，审阅后提交到master。
workflow已同步544M检查；Dockerfile的源码md5 pin也已同步。新的前端脚本纳入镜像代码指纹，避免挂载卷继续使用旧代码。
等GitHub Actions构建和验证成功，再按你原来的部署命令更新容器，保留现有环境变量、端口、挂载路径和数据库。

## 容量和速度

354.62MiB分成8片（7个50MiB加最后约4.62MiB）。3个并发可能改善单连接表现，不保证带宽提升。
合并时同时保留分片和完整临时文件，单张512MiB文件暂存峰值约1GiB，除此之外还有PHP临时上传文件和应用缓存。
50MiB分片加表单开销仍小于Cloudflare免费版/Pro的100MB单次限制；请求路径、WAF、其他反代限制和超时也需允许。

## 回退热补丁

使用安装时打印的备份目录，把其中的 app/、routes/、resources/、public/ 原文件复制回 /var/www/html 对应位置；只删除 new-files.txt 列出的补丁新增文件。
恢复 php-previous.ini；如果安装前没有该文件，则删除 /usr/local/etc/php/conf.d/zz-upload-chunks.ini。
删除本补丁生成的 /etc/cron.d/lsky-upload-chunks-lsky-pro，清理view/route缓存并平滑重载Apache。
不要删除数据库、storage/app/public、.env或整个数据卷。
